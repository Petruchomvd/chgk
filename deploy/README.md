# Развёртывание CHGK на личном сервере

Целевая схема:

- код: `/opt/chgk/current`;
- Python-окружение: `/opt/chgk/venv`;
- рабочие базы: `/var/lib/chgk/chgk_analysis.db` и `/var/lib/chgk/training.db`;
- переменные окружения: `/etc/chgk/chgk.env`;
- API: `127.0.0.1:8000`;
- веб-интерфейс до подключения домена: `127.0.0.1:8080` через SSH-туннель.

Базы никогда не размещаются внутри Git-клона. Перед переносом активной SQLite-базы
создаётся согласованный снимок средствами SQLite. После запуска сервер становится
основным местом хранения обеих баз, а Mac — местом проверенной резервной копии.

Службы:

- `chgk-api.service` — сайт и тренировки;
- `chgk-bot.service` — Telegram-бот с персональными тренировками;
- `chgk-update.service` — безопасное обновление каталога;
- `chgk-update.timer` — ежедневный запуск обновления.

До подключения домена сайт открывается на Mac командой `chgktunnel`, после чего
доступен по адресу `http://127.0.0.1:8080`.

Публичный адрес сайта: `https://play.nordvel.ru`. HTTP перенаправляется на
HTTPS, запросы по одному IP-адресу без правильного имени отклоняются.
Сертификат Let's Encrypt продлевается системным таймером Certbot. Локальный
SSH-туннель остаётся запасным способом входа.

Публичный сайт защищён собственной авторизацией приложения. Пароли хранятся
только как стойкие `scrypt`-хэши в `training.db`, сессии подписываются секретом
из `/etc/chgk/chgk.env` и передаются в `HttpOnly`/`Secure` cookie. Изменяющие
запросы требуют отдельный CSRF-токен, перебор веб-пароля ограничивается.
Секрет сессий задаётся переменной `CHGK_SESSION_SECRET`, а
`CHGK_COOKIE_SECURE=1` запрещает передачу cookie без HTTPS.

Аккаунты создаются администратором через `scripts/manage_users.py`; пароль
читается скрыто или из stdin и не передаётся в аргументах. Аккаунт Матвея
использует прежний внутренний идентификатор Telegram, поэтому существующие
попытки и очередь повторений сохраняются без миграции данных. Старый
`/etc/nginx/.htpasswd` после перехода не используется.

SSH принимает только ключ пользователя `matvey`: root, парольный вход, X11,
agent forwarding и удалённые туннели отключены. Локальный port forwarding
оставлен для запасной команды `chgktunnel`.

## Telegram-бот

`chgk-bot.service` запускает существующий aiogram-бот из `bot/main.py` под
непривилегированным пользователем `chgk`. Токен, owner ID и список разрешённых
Telegram ID находятся только в `/etc/chgk/chgk.env`:

- `CHGK_BOT_TOKEN`;
- `CHGK_BOT_OWNER_TG_ID`;
- `CHGK_BOT_ALLOWED_TG_IDS`.

Секреты не хранятся в Git. Бот работает только в личных сообщениях и использует
общий тренировочный движок и серверную `training.db`; прогресс разделяется по
Telegram user ID. Для добавления участника его ID включается в allowlist.

## Резервные копии на сервере

`chgk-backup.timer` ежедневно запускает root-службу
`chgk-backup.service`. Она создаёт согласованные SQLite-снимки в
`/var/backups/chgk`, выполняет `PRAGMA quick_check`, сохраняет SHA-256 и
оставляет семь последних копий. Каталог и файлы доступны только root, поэтому
пользователь веб-приложения `chgk` не может изменить или удалить эти копии.

## Резервная копия на Mac

Скрипт `pull-backup-to-mac.sh` создаёт согласованные снимки обеих активных
SQLite-баз на сервере, переносит их в `~/Backups/myos/chgk`, проверяет
`PRAGMA quick_check` и сохраняет контрольные суммы. По умолчанию остаются
четыре последние еженедельные копии.

Файл `com.matvey.myos.chgk-backup.plist` запускает скрипт по воскресеньям
в 06:00 по локальному времени Mac. Если компьютер спит, macOS выполнит
пропущенный запуск после пробуждения.
