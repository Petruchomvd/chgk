# Хранение базы CHGK

## Главное правило

`chgk_analysis.db` является рабочими данными, а не исходным кодом. База хранится локально и больше не должна попадать в новые Git-коммиты или Git LFS.

По умолчанию приложение использует файл `chgk_analysis.db` в корне проекта. Путь можно переопределить переменной окружения:

```env
CHGK_DB_PATH=/var/lib/chgk/chgk_analysis.db
```

Относительный путь считается от корня проекта. Для сервера рекомендуется абсолютный путь за пределами Git-клона.

## Перенос на сервер

1. Создать согласованную резервную копию средствами SQLite, а не копировать активно записываемый файл вслепую.
2. Передать копию на сервер отдельным защищённым способом.
3. Поместить её, например, в `/var/lib/chgk/chgk_analysis.db`.
4. Выдать пользователю приложения права на чтение и запись.
5. Задать `CHGK_DB_PATH` в серверном `.env` или конфигурации службы.
6. Проверить `PRAGMA quick_check` и запуск приложения.

## Резервирование

- Git хранит код, схему и миграции, но не рабочую базу.
- Для базы нужна отдельная регулярная резервная копия с ограниченным сроком хранения.
- Минимально следует хранить несколько последних проверенных копий и периодически проверять восстановление.
- Папки `.backups/` и `data/backups/` не отправляются в Git.

## Существующая история Git LFS

Старые версии базы уже присутствуют в истории Git LFS. Прекращение отслеживания остановит дальнейший рост, но само по себе не освободит ранее использованное место. Очистка удалённой LFS-истории потребует отдельной контролируемой операции с переписыванием истории и не должна выполняться автоматически.
