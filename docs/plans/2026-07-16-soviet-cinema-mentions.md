# Аналитика упоминаний советского кино и персонажей

**Дата:** 2026-07-16
**Статус:** Выполнен

## Контекст

Следующая содержательная задача после завершения пайплайна сложности: выяснить, какие
советские фильмы и персонажи чаще всего встречаются отдельно в трёх полях `questions`:
`text`, `answer`, `comment`.

Требования пользователя:

- не только рейтинги, но и доказательства каждого совпадения;
- защита от омонимов (короткое имя без контекста не считается достаточным);
- отчёт о покрытии данных;
- исходные вопросы не меняются;
- словарь сущностей — отдельный и воспроизводимый.

Решения по охвату, согласованные с пользователем 2026-07-16:

1. **Охват кино:** всё кино производства СССР — игровое, мультфильмы, телефильмы
   (Wikidata `P495 = СССР`). У каждого фильма в словаре хранится тип, чтобы разбивку
   можно было показать отдельно.
2. **Персонажи из литературы** (Остап Бендер, Штирлиц): считаются, но помечаются
   литературным первоисточником (Wikidata `P144`), чтобы пользователь сам решал,
   засчитывать ли упоминание кино или книге.
3. **Хранение:** новые производные таблицы в `chgk_analysis.db` + файловый отчёт.
   Исходные вопросы не изменяются, таблицы пересобираются идемпотентно.

## Ключевая проблема — омонимия

Названия советских фильмов сплошь состоят из обычных фраз и часто совпадают с
литературными первоисточниками: «Война и мир», «Собачье сердце», «Двенадцать стульев»,
«Судьба человека», «Дама с собачкой». Простое совпадение строки не доказывает, что
имеется в виду фильм. Поэтому:

- совпадение никогда не считается фактом само по себе — у него есть правило и уровень
  уверенности;
- уровень уверенности выводится из проверяемых признаков, а не из ощущений;
- все совпадения сохраняются с доказательствами, а отбраковка — с причиной.

## План

### Этап 1 — словарь (`scripts/build_cinema_dict.py`)

Источник: Wikidata SPARQL (публичный endpoint, User-Agent с контактом, батчи).

1. Фильмы: `?f wdt:P31/wdt:P279* wd:Q11424` (+ мультфильмы/телефильмы) и
   `wdt:P495 wd:Q15180`. Поля: QID, ru-label, ru-алиасы, год (P577), режиссёр (P57),
   первоисточник (P144), тип (P31), ссылка на ru.wikipedia.
2. Персонажи: `P674` (персонажи фильма) + роли из `P161`/`P453`. Поля: QID, ru-label,
   ru-алиасы, фильмы, актёр.
3. Признак омонимии — вычисляемый, а не ручной: для каждой ru-метки словаря отдельным
   запросом ищутся другие сущности Wikidata с той же меткой и другим типом
   (роман, песня, город, термин). Найденные конкуренты сохраняются в словаре как
   `homonyms` — это и есть автоматическое обоснование риска.
4. Снапшот сохраняется вместе с текстом SPARQL-запросов, датой и счётчиками в
   `data/soviet_cinema/`: `films.json`, `characters.json`, `dict_meta.json`.
   Ручные правки — только в отдельном `hints.json` (по образцу `wiki_hints.json`),
   снапшот не редактируется руками.

### Этап 2 — модуль сопоставления (`cinema/`)

- `cinema/dictionary.py` — загрузка снапшота, построение алиасов и индекса.
- `cinema/matcher.py` — нормализация, поиск, контекст, уровень уверенности.
- `cinema/store.py` — идемпотентная запись в БД.
- `cinema/report.py` — отчёт и покрытие.

Нормализация: lower, ё→е, снятие ударений, схлопывание пробелов, лемматизация
(pymorphy3). Переиспользуются `normalize_answer_key()` и `ALL_STOPWORDS` из
`scripts/analyze_answers.py`.

Правила сопоставления и уровни уверенности:

| Правило | Уровень |
|---|---|
| `quoted_title_exact` — название в «ёлочках»/кавычках точно совпало | high |
| `quoted_title_lemma` — то же после лемматизации | high |
| `title_with_cinema_context` — голое название + киномаркер рядом | high |
| `title_with_creator_context` — голое название + фамилия режиссёра/актёра рядом | high |
| `bare_title_multiword_distinctive` — длинное небанальное название без контекста | medium |
| `character_full_name` — имя + фамилия персонажа | high |
| `character_rare_surname` — редкая уникальная фамилия (Штирлиц, Новосельцев) | medium/high по контексту |
| `character_common_name_with_context` — обычное имя + киномаркер | medium |

Отбраковывается совсем (с записью причины):

- односложные названия-омонимы без киноконтекста («Вий», «Гараж», «Аврора»);
- совпадения, где рядом маркер первоисточника («роман», «повесть», «Булгаков»),
  а киномаркера нет;
- имена из стоп-листа частотных русских имён без фамилии и без контекста.

Киномаркеры контекстного окна: фильм, кинофильм, кинокартина, картина, лента,
комедия, мультфильм, телефильм, сериал, экранизация, режиссёр, снял, снят, роль,
сыграл, актёр, актриса, кадр, эпизод, реплика, Мосфильм, Ленфильм, Союзмультфильм.

Доказательство каждого совпадения: `question_id`, поле, точный найденный фрагмент,
смещение, контекстное окно, правило, уровень уверенности, ID сущности словаря.

### Этап 3 — схема

В `database/schema.sql` (идемпотентный `CREATE TABLE IF NOT EXISTS`):

- `cinema_entities` — сущность словаря: `id` (QID), тип (film/character), название,
  год, режиссёр, первоисточник, признак омонимии, версия словаря;
- `cinema_mentions` — упоминание: `question_id`, `entity_id`, `field`, `rule`,
  `confidence`, `matched_text`, `start_offset`, `context`, `run_id`;
- `cinema_runs` — прогон: `id`, дата, версия словаря, хэш словаря, счётчики,
  параметры. Нужен для воспроизводимости и идемпотентности.

Исходные таблицы не трогаются. Перед первой массовой записью — резервная копия.

### Этап 4 — оркестратор (`scripts/analyze_cinema.py`)

```bash
python scripts/analyze_cinema.py --dry-run
python scripts/analyze_cinema.py --limit 5000
python scripts/analyze_cinema.py            # полный прогон
python scripts/analyze_cinema.py --report   # только отчёт из БД
```

Отчёт содержит:

- топ фильмов и топ персонажей **отдельно** по `text`, `answer`, `comment`;
- число уникальных вопросов, а не только число упоминаний;
- разбивку по уровням уверенности (рейтинг по умолчанию — только high);
- покрытие полей: сколько вопросов вообще имеют текст, ответ, комментарий;
- примеры доказательств для каждой верхней позиции;
- список отбракованных совпадений с причинами.

### Этап 5 — проверка

- модульные тесты `tests/test_cinema_matcher.py`: нормализация, кавычки, омонимы,
  контекстное окно, литературный первоисточник, идемпотентность, `--dry-run`;
- ручная выборочная проверка не менее 30 совпадений разных правил;
- контроль, что число вопросов и тематических связей не изменилось;
- `foreign_key_check` и `quick_check`.

## Известное ограничение окружения

`pymorphy3` не установлен ни в одном интерпретаторе; системный Python 3.9 имеет
pymorphy2 и natasha, `.venv` (3.12) — ничего. Перед прогоном нужно установить
NLP-зависимости в `.venv`.

## Дополнение: актёры и режиссёры (2026-07-16)

Первая версия искала только фильмы и персонажей — актёры использовались лишь
как контекстная подсказка. По просьбе пользователя добавлены люди кино.

Согласованные решения:

1. **Считать всё, но раздельно**: «в киноконтексте» и «вне его». Половина
   советских актёров знаменита не кино: Высоцкий — бард, Никулин — клоун.
2. Добавить и актёров (5 366), и режиссёров (1 799).

Устройство: уверенность и киноконтекст — **разные измерения**. Уверенность
отвечает «тот ли это человек», `cinema_context` — «в какой роли упомянут».
Смешивать их в одном уровне нельзя.

Потребовались три фильтра, каждый выявлен на реальном топе:

- **Род занятий (P106).** Wikidata числит «в ролях» всех, чья хроника попала
  в документальный фильм: Сталин и Геринг были в топе актёров. По профессии
  видно, что они политики.
- **Порог узнаваемости по фамилии (3 фильма).** «Чаплин, Станислав Викторович»
  — режиссёр одного фильма — перехватывал все 76 вопросов про Чарли Чаплина.
  Так же вели себя Арнольд, Тиме, Бертонов (1–2 фильма).
- **Разворот инвертированных имён.** В Wikidata «Гайдай, Леонид Иович», в
  вопросах — «Леонид Гайдай». Без разворота такие люди находились бы только
  по голой фамилии, которую первый фильтр как раз отбирает.

Попутно исправлено: `sync_entities` не удалял сущности, выпавшие из словаря
(в таблице оставалось 403 отсеянных человека), а в отчёте колонки по полям
считали упоминания, тогда как «Вопросов» — вопросы, из-за чего получалось
«104 в киноконтексте при 76 вопросах».

## Результат

Реализовано и проверено на полной базе 2026-07-16.

### Что получилось

- Словарь из Wikidata: 8 589 фильмов производства СССР, 580 персонажей и
  6 416 людей кино (после фильтров). Снапшот вместе с текстами SPARQL-запросов
  — в `data/soviet_cinema/`.
- Прогон по 212 779 вопросам занимает ~95 секунд, находит 46 653 упоминания
  и объясняет 1 400 802 отбраковки. Подтверждённых (high) упоминаний:
  4 216 вопросов с людьми кино, 2 824 с фильмами, 520 с персонажами.
- Исходные таблицы не изменились: 6 957 пакетов, 212 779 вопросов,
  52 386 тематических связей, 124 413 статистик сложности —
  цифры совпадают с состоянием до прогона. `foreign_key_check` чист,
  `quick_check` вернул `ok`.
- Повторный полный прогон даёт ровно те же 46 653 упоминания и один прогон
  в `cinema_runs` — пайплайн идемпотентен.
- Тесты: 60 новых, всего в проекте 105, все проходят.
- Отчёт: `docs/reports/2026-07-16-soviet-cinema.md`.

Топ фильмов (по числу вопросов с подтверждённым упоминанием): Бриллиантовая
рука (107), Белое солнце пустыни (97), Кавказская пленница (91), Джентльмены

### Чем решалась омонимия — итоговый набор признаков

План предполагал, что хватит кавычек, киномаркеров и данных об омонимах.
На практике первый прогон дал мусорный топ (фильм «Одна» 1931 года — 882
ложных совпадения со словом «одна»), и потребовались дополнительные признаки:

1. **Частотность лемм по самой базе** (`cinema/frequency.py`) — главный
   признак. Морфология для этого не годится: pymorphy знает «чебурашка» как
   обычное существительное, а «спасибо» считает редким. Данные базы говорят
   правду: «один» — в 37.8% вопросов, «чебурашка» — в 0.042%.
2. **Заглавная буква.** «трус» — характеристика, «Трус» — герой Вицина.
3. **ЧГК-замены капсом.** «ОНИ», «ИКС» — подстановки, а не названия.
4. **Ближнее окно (70 символов).** На радиусе 160 слово «фильм» есть почти
   в любом вопросе про кино, и любое совпавшее слово получало high.
5. **Реальные люди — не персонажи.** Wikidata числит «персонажами» Ленина
   и Эйнштейна; 671 такая запись исключена.
6. **Омонимы на уровне формы названия, а не фильма.** У «Первых огней» (1925)
   альтернативное название «Маяк»; без этого оно ловило радиостанцию и
   химкомбинат.
7. **Одноимённое чужое кино** (`has_film_homonym`). «В фильме „Джокер“» не
   доказывает, что речь о советском «Джокере» 1991 года.
8. **Ответ судится по тексту вопроса.** Ответ «Юрий Гагарин» — про космонавта,
   а не про одноимённый фильм 1969 года, если в вопросе нет ни слова о кино.
9. **Предлоги не считаются длиной названия.** «Смотри в корень» — поговорка
   из двух слов, а не небанальная трёхсловная фраза.

Каждый признак закрыт тестом-регрессией.

### Отклонения от плана

- Пагинация SPARQL (`LIMIT/OFFSET` + `GROUP BY`) роняла публичный endpoint в 500.
  Заменена на плоские запросы целиком с группировкой в Python — 8.5k строк
  за ~6 секунд. Запросы уходят POST'ом: `VALUES` с сотней названий не
  помещается в URL (414).
- Резервная копия делается своей функцией, а не `create_backup()` из
  `update_catalog.py`: та удаляет старые копии (`keep=3`) и снесла бы копии
  этапа сложности, перечисленные в передаче сессии.
- `pymorphy3` не был установлен ни в одном интерпретаторе — поставлен в `.venv`
  (там же не было `pytest`, `natasha`, `aiogram`).

### Известные ограничения

Перечислены в отчёте (раздел 7). Главные: словарь персонажей беден
(в Wikidata размечено ~2 тыс. персонажей, и рейтинг персонажей поэтому
неполон и состоит в основном из героев экранизаций); лемматизация склеивает
«Происхождение видов» Дарвина с фильмом «Происхождение вида» (1966);
в альтернативных названиях Wikidata попадается мусор — лечится через
`data/soviet_cinema/hints.json`.
