# Редизайн веб-приложения: «Картотека»

**Дата:** 2026-07-16
**Статус:** Выполнен

## Контекст

Задача — полный продуктовый редизайн веб-приложения для подготовки к ЧГК.

### Что выяснилось при анализе (важно)

Бриф исходил из предпосылок, которые не совпали с реальностью проекта:

1. **Стек.** Приложение написано на **Streamlit** (Python, ~3800 строк в `dashboard/`).
   React/`package.json`/Node в проекте отсутствовали. shadcn/ui — React-библиотека,
   в Streamlit невозможна без замены фронтенда.
2. **Несуществующие функции.** В брифе заявлены как существующие, но в коде отсутствуют:
   избранное, личные заметки, прогресс по темам, полнотекстовый поиск
   (реально — `LIKE '%...%'` без FTS-индекса).
3. **Главная находка.** В `app/training_engine.py` есть полноценный UI-agnostic движок
   обучения: Leitner (5 боксов), история попыток, режим повторения, запись в `training.db`.
   Но его использует **только Telegram-бот** (`bot/handlers/training.py`).
   Веб-тренировка (`dashboard/training.py`) — отдельная дублирующая реализация,
   которая пишет результаты **только в `st.session_state`**.
   → **Весь прогресс веб-тренировки теряется при закрытии вкладки.**
   Веб-приложение фактически было дашбордом для оценки LLM-классификаторов
   с прикрученным одноразовым квизом, а не инструментом подготовки.
4. **Данные.** 212 779 вопросов, но классифицировано только **27 706 (13%)**.
   Фильтры по темам молча применяются к меньшинству базы.
   6 957 пакетов, 2000–2026 гг.
5. **Баг.** `search_questions` делает `LEFT JOIN question_topics` без дедупликации —
   вопрос, классифицированныйN моделями, показывается N раз.

### Решения пользователя

- **Стек:** переписать фронтенд на React + shadcn/ui, Python остаётся как API (FastAPI).
- **Объём функций:** из отсутствующего реализовать только **сохранение прогресса в вебе**.
  Избранное, заметки и FTS — вне объёма.

### Решение по объёму (принято при реализации)

Существующая аналитика (`Категории`, `Тренды`, `Рекомендации`, `Авторы`,
`Сравнение моделей`, `Уверенность`, `Джентльменский набор`, `Турнир IQ ПФО`) —
это инструмент исследования качества классификаторов, а не ежедневная подготовка.
В брифе он не упоминается. Порт этих страниц на React кратно превысил бы объём
самого учебного приложения.

→ **Streamlit-дашборд остаётся как есть и продолжает работать** для аналитики.
Новое React-приложение покрывает учебный контур. Функциональность не теряется.

## Дизайн-концепция

**«Картотека»** — читальный зал и картотека исследователя, а не викторина.

- **Палитра:** графитово-синяя навигация (`#1B2430`), тёплый бумажный фон (`#F7F4EE`),
  тёмный текст (`#23282E`), приглушённый янтарь как акцент (`#B8862F`),
  спокойный зелёный (`#4F7A5B`) и терракота (`#A8543C`) для ответов.
- **Типографика:** serif с кириллицей для длинных текстов вопросов,
  Inter для интерфейса. Вопрос — крупный, с большим line-height.
- **Композиция:** тёмная левая панель, плотная рабочая область, без hero-блоков,
  без карточки на каждый факт, без градиентов и скруглений-«пилюль».

## Информационная архитектура

| Раздел | Назначение |
|---|---|
| Обзор | Продолжить, повторения на сегодня, слабые темы, статистика |
| Картотека | Поиск + фильтры + плотный список 212k вопросов |
| Вопрос | Полный текст, ответ, зачёт/незачёт, комментарий, источник, история попыток |
| Темы | Дерево категорий, покрытие, прогресс, старт тренировки |
| Тренировка | Один вопрос в фокусе, клавиатура, «Знал / Почти / Не знал» |
| Повторение | Leitner-очередь на сегодня |

Из предложенной в брифе структуры:
- **Сохранено:** Обзор, База вопросов (→ «Картотека»), Темы, Тренировка, Повторение.
- **Убрано:** «Избранное» (нет данных — вне объёма), «Настройки» (нечего настраивать
  в однопользовательском приложении; фильтры живут на своих страницах).
- **Изменено:** «Ошибки» и «Повторение» объединены — Leitner уже покрывает оба смысла.

## План

1. Установить Node (через Homebrew) — отсутствовал в системе.
2. FastAPI-слой (`api/`) поверх существующих модулей:
   переиспользовать `db_queries`, `training_queries`, `training_engine`, `training_db`.
   Не дублировать логику.
3. React + Vite + TS + Tailwind + shadcn/ui (`web/`).
4. Дизайн-система: токены, типографика, компоненты поверх shadcn.
5. Страницы учебного контура.
6. **Подключить веб-тренировку к `training_engine`** → попытки и Leitner сохраняются.
7. Запуск, проверка сценариев, скриншоты 1440px и 390px, итерации.

## Затронутые файлы

- `web/` — новое React-приложение
- `dashboard/` — **не трогаем** (аналитика продолжает работать)

## Результат

Реализовано. Запуск: `./scripts/run_web.sh` → http://localhost:5173

### Что сделано

- **`api/`** — FastAPI-слой поверх существующих модулей. Логика обучения не
  продублирована: используется `app/training_engine.py` — тот же движок, что у бота.
- **`web/`** — React 19 + Vite + TypeScript + Tailwind v4 + shadcn/ui (Base UI).
  Дизайн-система «Картотека»: токены, типографика, состояния.
- **Главное: веб-тренировка сохраняет прогресс.** Попытки и Leitner пишутся в
  `training.db` под тем же `user_id`, что и у бота (`_legacy_user_id()`),
  поэтому история у бота и веба общая. Проверено сквозным сценарием.
- Streamlit-дашборд не тронут и работает как раньше.
- 106 тестов проходят.

### Найденные и исправленные проблемы

1. **Прогресс не сохранялся.** `dashboard/training.py` дублировал логику квиза
   и писал только в `st.session_state`. Теперь веб использует `training_engine`.
2. **Ложное «пусто» при недоступном API.** React Query при недоступном бэкенде
   уходит в `fetchStatus: 'paused'` с `error: null` → страница показывала
   «База ещё не классифицирована», то есть врала. Добавлен `loadError()`:
   пауза распознаётся как «сервер недоступен» с командой запуска.
   Страницы используют `isPending` вместо `isLoading`, чтобы «данных ещё нет»
   никогда не рендерилось как «пусто».
3. **Дубли в списке вопросов.** `db_queries.search_questions` делает
   `LEFT JOIN question_topics` без дедупликации → вопрос, размеченный N моделями,
   возвращался N раз. В `api/catalog.py` используется `ROW_NUMBER() OVER
   (PARTITION BY question_id)` — одна строка на вопрос.
   **Баг остался в Streamlit-дашборде** (его не трогали) — стоит починить отдельно.
4. **Бесполезная витрина по умолчанию.** Сортировка по `q.id DESC` выносила
   наверх поздний импорт без дат (пак «db.chgk.info — yukalyakin», 938 вопросов).
   По умолчанию — свежие турниры (`published_date DESC`).
5. Грамматика: «1 вопрос ждут повторения» → «ждёт»; «1 вопрос пройдено» → «пройден».
6. Плотность списка на телефоне: превью в 260 символов давало 6 строк — добавлен
   `line-clamp-2`.
7. Кнопка «тренировка по теме» была видна только по ховеру — недоступна на тач-экранах.

### Осознанные отступления от брифа

- **Три оценки («Знал / Почти знал / Не знал») не сделаны.** Движок хранит
  `attempts.knew` как булево и общий с ботом; третья градация потребовала бы
  менять схему и логику Leitner для обоих клиентов — это за рамками
  «сохранения прогресса». Сделаны две кнопки.
- **«Избранное», «Заметки», FTS** — вне объёма по решению пользователя.
- **«Настройки»** — убраны: в однопользовательском приложении настраивать нечего,
  фильтры живут на своих страницах.
- **Аналитика (8 страниц + турнир IQ ПФО) не портирована** — осталась в Streamlit.
  Это инструмент оценки классификаторов, а не ежедневная подготовка.

### Известные ограничения

- Сессия тренировки живёт в памяти процесса API: перезапуск сервера теряет
  незавершённую сессию (уже оценённые вопросы сохранены). UI показывает это
  честно и предлагает начать заново.
- Темы доступны только для 13% базы (27 742 из 212 779) — это состояние данных,
  в интерфейсе указано прямо.
- Сложность известна у ~53% вопросов (113 538).
- Поиск — `LIKE '%...%'` (~0.2–0.7 с на 212k). Приемлемо, но FTS5 ускорил бы.
