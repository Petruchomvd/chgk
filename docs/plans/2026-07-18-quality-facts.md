# Качественные «берущиеся» факты по темам

**Дата:** 2026-07-18
**Статус:** Реализовано (пайплайн + UI) + демо-прогон по слабым темам

## Контекст / проблема

В контуре «Учить» досье факта показывает комментарии к вопросам. Пользователь
верно заметил: факты «криво сформированы». Причина — комментарии написаны как
пояснения к КОНКРЕТНОМУ вопросу и не читаются как самостоятельные факты
(«Тевье говорит…», «после казни врачи просили жертв…», часть пустые).

Ранее пробовали два подхода (data/gentleman_set):
- `edu_facts_cache` (из статей Arzamas): «берущиеся», но свалка гипер-специфичного
  тривиала без ядра «кто это и почему спрашивают».
- `wiki_facts_cache` (из Википедии): чистые и связные, но generic — не про то,
  что реально спрашивает ЧГК.
Оба используют один generic-промпт «выдели 7–10 интересных фактов» — не привязан
ни к корпусу, ни к «берущимся» углам.

## Ключевая находка (эмпирически)

Источники комплементарны:
- **Wikipedia-лид = чистое, точное ЯДРО** (для Герострата — идеально: сжёг храм
  Артемиды в Эфесе, 356 до н.э., ради славы; приговорён к забвению — но помним).
- **Корпус (вопросы + разборы) = ходовые ЗАЦЕПКИ** — то, что авторы эксплуатируют
  (для гильотины: Сансон, проверка сознания после казни, метафора революции —
  этого в вики-лиде нет).

## Метод (доказан на Герострате/гильотине/зеркале)

Для сущности E:
1. **Собрать сырьё**: (A) Wikipedia-выжимка (точность ядра) + (B) корпусные углы —
   тексты вопросов и разборы, где E — ответ (уже есть: `app/study.fact_dossier`).
2. **Синтез LLM** (gemma@openrouter) в структурированную карточку:
   - `ядро`: 1–2 предложения, что это;
   - `зацепки[]`: {факт (самостоятельный), угол (как спрашивают), цитата (дословная
     опора из A/B)}.
   Промпт корпус-осознанный: приоритет зацепкам, встречающимся в (B) не раз.
3. **Проверка заземления (антигаллюцинация, без второй модели)**: модель обязана
   дать ДОСЛОВНУЮ цитату-опору; Python проверяет перекрытие слов цитаты с сырьём
   (порог 0.6). Факт без опоры → «не подтверждён», в учебник не идёт. На прототипе
   отбраковал факт с пустой/выдуманной опорой.
4. **Схема ответа**: принудительный JSON (инфра уже есть в классификаторе) — иначе
   модель плавает по именам ключей.

Результат прототипа (примеры): карточки чистые, самостоятельные, точно попадают в
ЧГК-углы (парадокс damnatio memoriae, связь с рождением Александра, династия
Сансонов, «Шотландская дева», подглядывание масти через зеркало) — радикально
лучше комментов и старых edu_facts.

## Стоимость / масштаб

~1 вызов gemma на сущность (~800/800 токенов) ≈ $0.0003. Канон слабых тем — сотни
сущностей → ~$0.15–0.6 на весь учебник. Проверка бесплатна (Python). Кэшируемо,
инкрементально.

## План реализации (по согласованию)
- `scripts/gen_facts.py`: канон → (A)+(B) → синтез со схемой → grounding-QC → кэш
  `data/facts/fact_cards.json` (по ключу-ответу).
- Эндпоинт `/api/study/fact` отдаёт карточку (если есть) + углы как «примеры».
- Страница «Учить»: показывать ЯДРО + ЗАЦЕПКИ сверху, комменты — ниже как примеры.
- Демо-прогон на ~50 сущностях слабых тем (~$0.02) для проверки в UI, полный — позже.

## Альтернативы (рассмотрены, отклонены как основной путь)
- Чисто экстрактивно (без LLM): брать самодостаточные предложения комментов —
  дёшево, но большинство комментов привязаны к вопросу. Годится как фолбэк.
- Только Wikipedia, отфильтрованная корпусом: verbatim-безопасно, но теряет
  зацепки не из лида. Хорошо для сущностей без корпусного сигнала.

## Результат

Реализовано:
- `scripts/gen_facts.py` — генератор карточек (вики+корпус → синтез со схемой →
  grounding-QC → кэш `data/facts/fact_cards.json`), инкрементально, с паузами.
  Флаги `--weak`/`--category-ids`/`--answers`/`--per-cat`/`--force`.
- `/api/study/fact` отдаёт `card` (ядро + только подтверждённые заземлением
  зацепки); страница «Учить» показывает карточку сверху, вопросы — ниже как примеры.
- Демо-прогон по канону слабых тем (~64 сущности, ~$0.02). В UI проверено:
  карточка Герострата — чистое ядро + 7 самостоятельных зацепок с углами.

Наблюдения:
- Заземление стабильно высокое (7–8 из 7–8 зацепок подтверждаются); модель, где
  придумывает факт без опоры, ловится проверкой цитаты (Бетховен 4/6).
- Подводный камень: `create_provider` берёт ключ из `os.environ`; ключ в среду
  кладёт импорт `config` — вызывать провайдер только после импорта config.

Следующее (по согласованию): полный прогон по всему канону; спейс-повторение
изученных фактов; перенос карточек в Telegram-бота.
