# Модель команды из полной истории rating.chgk

**Дата:** 2026-07-18
**Статус:** Выполнен

## Контекст

Цель сессии: превратить проект в «ультимативный инструмент подготовки к турнирам».
Аудит показал главное узкое место — **сигнал о собственной игре команды тонкий**:
внутренних попыток почти нет (72 записи, 1 игрок; `team_training_answers` пуста),
а весь диагноз держится на 132 вопросах из 3 турниров (`team_gap`), где на категорию
приходится n=2..12 — статистически шатко.

Проверенная гипотеза: **rating.chgk отдаёт маски всех команд по каждому турниру**,
а значит беручесть поля считается прямо из данных рейтинга — дефицит «команда vs поле»
доступен для любого турнира без привязки к нашей БД. Текущий состав (с 2024-02) сыграл
8 турниров, 6 с масками → ~394 сыгранных вопроса вместо 132 (×3 сигнала).

Проверенные находки:
- Общий дефицит команды к полю ≈ −3 п.п. (47.2% против 50.3% поля на 394 вопросах).
- **Калибровочная кривая**: дефицит сконцентрирован в полосе беручести 20–60%
  (−6.6 и −6.8 п.п.), на лёгких (80–100%) команда обыгрывает поле (+2.0),
  на трудных (0–20%) идёт вровень. Вывод: теряете «средние» вопросы, не гиммы и не
  безнадёги. Это эмпирически задаёт зону тренировок ≈ 20–65%, а не угаданные 35–70%.
- Позиционный эффект в туре — шум (n≈34/позицию, длина тура непостоянна), не используем.

## План

1. `scripts/team_history.py` — авто-досье:
   - тянет турниры команды из `api.rating.chgk.info/teams/{id}/tournaments`;
   - по маскам: дефицит vs поле по турниру, калибровочная кривая, тренд;
   - матчит турнир к пакету БД по корреляции беручести → разрез по темам/приёмам;
   - пишет `data/team/team-{id}-gaps.json` (совместимая схема + `calibration`,
     `focus_band`) и `docs/reports/team-{id}-history.md`.
2. Калибровочная модель win-prob `P(команда берёт | беручесть поля)` +
   `forecast(pack)` — ожидаемый счёт команды и swing-вопросы.
3. `start_team_gap`: `take_rate_range` из `profile['focus_band']` (fallback 0.35–0.70).

## Результат

Сделано полностью:
- `scripts/team_history.py` — авто-досье (6 турниров, 394 вопроса), калибровочная
  кривая, `focus_band` (30–60%), логистическая модель win-prob, режимы
  `--forecast`/`--validate`. Матчинг пакетов по корреляции + gotquestions-фолбэк
  (категории на 144 вопросах: B-52 + Крафтик + Поволжская).
- `app/training_engine.py` — `start_team_gap` читает `focus_band` и фильтрует
  темы по n≥5.
- API `/api/team/dossier` + `/api/team/forecast`; веб-страница `/team`
  (`web/src/pages/TeamDossier.tsx`), пункт навигации, роут. Фронт собирается,
  проверено в браузере end-to-end (прогноз на пакет работает).

Валидация модели (LOO): средняя ошибка прогноза счёта ~7 вопросов, но почти вся
из одного турнира-выброса (команда сыграла +13.5 к полю); на остальных ±1..7.
Покомпонентная калибровка точна (pred=actual=0.472). Прогноз подаётся с явной
оговоркой о разбросе ±7.

Не входит в этот этап (следующие рычаги): дозалить недостающие пакеты турниров
команды в БД (олимпиады ПФО — ещё ~250 вопросов для разреза по темам); прогноз/
досье в Telegram-боте; сбор внутренних попыток (`team_training_answers` пуста).
